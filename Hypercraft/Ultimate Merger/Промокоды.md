# Промокоды

# Цель системы
- Выдавать игрокам промокоды за активности (ивенты, конкурсы, партнёрки, тесты, компенсации).
- Игрок вводит код в UI, получает награду.
- Один и тот же код может иметь лимит активаций (общий) и лимит на игрока (1 раз на аккаунт).
# UI
В настройках в самом верху делаем кнопку, взять из окна обмена синюю. Иконка на кнопке qr код или штрих код.

Нажатие на кнопку открывает копию окна с обменом, но изменённым содержимым и другой высоты.
Вверху пояснительный текст: "Введите промокод, чтобы получить награду".
Ниже строчка для ввода справа от строчки кнопка с иконкой вставить. Функционал вставляет последнее из кэша.
Внизу кнопка активировать код. Иконку можно взять такую, как на кнопке подтвердить обмен.

Если промокод применён успешно подсвечиваем поле ввода зелёным, полученный предмет отображаем в стандартном бабле получения предметов. Если их список, то поочерёдно.

Если промокод не применён, подсвечиваем поле ввода красным, ниже него выводим ошибку:
- Неверный код
- Лимит активаций исчерпан
- Код истёк
- Вы уже активировали этот код
- Слишком много попыток, попробуйте позже ?(если есть какие-то системные ограничения)

## Не забыть сделать:
### Нормализация ввода до отправки:
- trim пробелы по краям
- приводить к UPPERCASE
### Состояния кнопки "Активировать":
- disabled, если поле пустое
- disabled + спиннер, пока идет запрос
- если запрос упал по сети, поле не красить как "неверный код", а показать "Ошибка соединения, попробуйте еще раз"
### Строка ввода кода
После успешной активации - очищать поле и писать Успешно на 1-2 секунды.
# Правила и ограничения
- Общий лимит успешных активаций (например 100).
- Дата/время начала.
- Дата/время окончания.
- Включён код или выключен (на случай экстренного изъятия из оборота).
- Лимит на аккаунт (по умолчанию 1 и давать возможность менять это пока не надо).

## Проверить
Выдача атомарная и не дублируется
- Сервер должен гарантировать, что при повторной отправке запроса награда не выдастся дважды (идемпотентность, request_id вероятно нужен?).
- Лимит активаций не должен "перепрыгиваться" при одновременных активациях (атомарное списание remaining_uses?).

# Награды: варианты наград
- Конкретный предмет
- Набор из нескольких позиций
- Случайные Н предметов из списка, может выпасть одинаковый
- Случайные Н предметов из списка, **не** может выпасть одинаковый
